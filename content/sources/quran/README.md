# Quran source data

Nothing in this directory except this file and `ENCODING_REPORT.md` is committed.

The Clear Quran translation is used **with the translator's permission**, and that
permission does not extend to redistributing it through this repository. So the
Quran data is downloaded by whoever builds the content database, not stored here.
`.gitignore` enforces that.

Everything else in this directory (`surahs.json`, `ayahs.json`) is generated by
`content/scripts/import_quran.py` and must never be hand-edited.

## What you need to download

QUL (<https://qul.tarteel.ai/>) publishes its data as downloadable files, one per
resource, in SQLite and JSON. There is no bulk read API to pull from, so this is a
manual, one-off download. Go to <https://qul.tarteel.ai/resources>, find each
resource below, and download it.

**Prefer the SQLite (`.db`) download wherever it is offered.** A plain JSON
translation and a plain JSON transliteration are byte-for-byte the same shape
(`{"1:1": "…"}`), so the importer cannot tell them apart on its own and will make
you disambiguate with a flag. The SQLite exports name their tables, so they are
unambiguous.

| # | Resource on QUL | Needed | Expected contents |
|---|---|---|---|
| 1 | Quran script — **Uthmani** | required | SQLite table `verses` with `verse_key`, `surah`, `ayah`, `text` |
| 2 | Translation — **The Clear Quran**, Dr. Mustafa Khattab | required | SQLite table `translations` (or `translation`) with `ayah_key`, `text` |
| 3 | Quran metadata — **Surah** | required | SQLite table `chapters` with `name_arabic`, `name_simple`, `revelation_place`, `verses_count` |
| 4 | Quran metadata — **Juz** | required | SQLite table `juz` with `verse_mapping` |
| 5 | Quran metadata — **Hizb** | required | SQLite table `hizbs` with `verse_mapping` |
| 6 | Quran metadata — **Sajdah** | recommended | SQLite table `sajdah` with `verse_key` |
| 7 | **English transliteration** | optional | SQLite table `transliterations` with `ayah_key`, `text` |

Without #6 every `ayahs.sajdah` is `0`. Without #7 every `ayahs.transliteration`
is `NULL`. Both columns are nullable/zero-defaulted, so the build still passes
verification.

## Where to put them

Drop the downloaded files here, keeping QUL's own filenames:

```
content/sources/quran/downloads/
```

The importer identifies files by looking inside them, not by their names, so you
do not need to rename anything. If two downloads look like the same kind of
resource it will stop and tell you to pick one with an explicit flag, e.g.
`--translation content/sources/quran/downloads/clear-quran.db`.

Check what it recognised before importing:

```bash
python3 content/scripts/import_quran.py --check
```

## Mushaf page numbers

`ayahs.page` is left `NULL` unless a page number can be found.

QUL's **mushaf layout** export is indexed by word (`first_word_id`,
`last_word_id`), not by ayah, so it cannot supply per-ayah page numbers without
also importing the full word-level dataset. Two things do work:

- Some QUL script exports (the glyph-based `code_v1` / `code_v2` scripts) carry a
  `page_number` column per verse. If your script download has one, it is picked up
  automatically.
- Otherwise pass `--pages <file>`, where the file is JSON mapping verse keys to
  page numbers: `{"1:1": 1, "2:1": 2, …}`.

Page numbers are not needed for v1.

## English surah names

QUL's chapter export has `name_arabic`, `name_simple` and `name` (a transliteration
with diacritics) — but no English *translation* of the surah name. So by default
`surahs.name_english` falls back to the plain transliteration and the importer
prints a warning.

To get real English names, supply your own file:

```bash
python3 content/scripts/import_quran.py --english-names my-names.json
```

where `my-names.json` is `{"1": "The Opening", "2": "The Cow", …}` covering all 114
surahs. The importer refuses a partial list.

## A note on `has_bismillah`

`surahs.has_bismillah` is derived as "1 for every surah except 9", **not** from
QUL's `bismillah_pre`. QUL sets `bismillah_pre` false for surah 1 as well, because
there the basmala is ayah 1 rather than a heading above it. That is correct for
QUL's purposes and wrong for ours, which is why the importer ignores that column.
